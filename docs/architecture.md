# Архитектура проекта

## Основные компоненты

```text
React-клиент (localhost:5173)
          |
          | HTTP + JSON + cookie клиента
          v
Flask API (localhost:5000)
    |                         |
    v                         v
сервис вычисления       репозиторий истории
                                  |
                                  v
                            файл SQLite
```

Пользователь работает с интерфейсом в браузере. React-клиент принимает
арифметическое выражение, отправляет его в Flask API и показывает полученный
ответ. Сам frontend ничего не вычисляет: весь разбор выражения и подсчёт
результата выполняются на backend.

После успешного вычисления backend сохраняет выражение и результат в SQLite.
Для каждого браузера создаётся отдельный идентификатор в cookie, поэтому
пользователь получает только собственную историю вычислений.

## Зоны ответственности backend

- `api/` принимает HTTP-запросы, проверяет их формат и формирует HTTP-ответы.
- `services/` содержит бизнес-логику: разбор выражения, вычисление результата и
  работу с идентификатором клиента.
- `models/` содержит описание таблиц базы данных через SQLAlchemy.
- `repositories/` отвечает за чтение и запись истории в SQLite.
- `extensions.py` создаёт общие расширения Flask, например объект базы `db`.
- `config.py` содержит настройки приложения и отдельные значения для тестов.
- `run.py` является точкой запуска backend.

Маршруты API специально разнесены по отдельным файлам. Благодаря этому
участники команды смогут работать в своих ветках и реже сталкиваться с
конфликтами при объединении кода.

## Как проходит вычисление

```text
1. Пользователь вводит выражение в React.
2. React отправляет POST /api/v1/calculate.
3. Flask проверяет JSON и длину выражения.
4. Calculator service разбирает выражение и считает результат.
5. При ошибке API возвращает HTTP 400 с понятным сообщением.
6. При успехе результат сохраняется в SQLite.
7. API возвращает результат клиенту в JSON.
8. React показывает результат пользователю.
```

Для получения истории React отправляет `GET /api/v1/history`. Backend читает
идентификатор клиента из cookie, выбирает из SQLite только его записи и
возвращает их от новых к старым.

## Модель данных

Студент 2 реализует сущность `Calculation` со следующими полями:

| Field | Type | Rules |
|---|---|---|
| `id` | integer | primary key |
| `user_id` | string | required and indexed |
| `expression` | string | required, maximum 512 characters |
| `result` | string | required |
| `created_at` | datetime | server-generated timestamp |

SQLite хранит всю базу в одном локальном файле. Отдельно устанавливать и
запускать сервер базы данных не требуется. Файл базы создаётся автоматически в
директории `instance/` и не добавляется в Git.

## Идентификация клиента

При первом успешном обращении backend создаёт случайный UUID и отправляет его в
cookie с именем `calculator_user_id`. Во всех следующих запросах браузер
отправляет этот cookie автоматически.

Cookie должен иметь как минимум следующие параметры:

- `HttpOnly` — JavaScript в браузере не может прочитать идентификатор;
- `SameSite=Lax` — базовая защита от отправки cookie с посторонних сайтов;
- разумный срок хранения, например 30 дней.

Авторизация и регистрация для Sprint 0 не нужны. Cookie используется только для
разделения истории разных браузеров.

## Граница безопасности

Выражение приходит от пользователя и считается недоверенным вводом. Нельзя
передавать его напрямую в обычный Python `eval`, потому что через API можно
отправить Python-код, которого нет среди кнопок интерфейса.

Сервис вычисления должен использовать один из двух подходов:

1. собственный parser арифметической грамматики;
2. Python AST со строгим списком разрешённых узлов и операций.

Разрешаются только числа, скобки, `+`, `-`, `*`, `/` и унарные знаки. Имена
переменных, вызовы функций, строки, атрибуты и другие конструкции Python должны
отклоняться.

Также backend ограничивает выражение 512 символами, корректно обрабатывает
деление на ноль и не сохраняет ошибочные запросы в историю.

## Интеграция frontend и backend

Во время разработки Vite работает на порту `5173` и перенаправляет запросы,
начинающиеся с `/api`, на Flask по адресу `127.0.0.1:5000`. Поэтому разработчику
не нужно вручную менять URL backend или создавать локальный `.env`.

Все участники ориентируются на единый контракт из `docs/api.md`. Если формат
запроса или ответа необходимо изменить, это сначала согласуется с командой и
одновременно обновляется в документации, backend, frontend и тестах.
